# Security model

What each component may do and how its traffic is protected. Hardening steps:
[Security guide](../guides/security.md).

## Identities

| Identity | Can | Cannot |
|---|---|---|
| operator ServiceAccount | manage StatefulSets, Services, PDBs, network policies, PVCs (patch only) and SQL pods; read, create and update Secrets cluster-wide; patch the control-record and epoch Leases | taint nodes, delete VolumeAttachments, delete Secrets |
| breakout ServiceAccount | taint nodes, delete VolumeAttachments and stuck pods | serve the webhook or the view API |
| `sa` on each SQL Server | everything: the operator connects as `sa` | — |

A dedicated, least-privileged operator login is not implemented: the operator uses `sa`. Stored
procedures are deployed through a separate login that is only `db_ddladmin` on the targeted
databases (`deployAs: LeastPrivilege`).

## Admission

The validating webhook refuses what the operator would refuse to run: privileged or root pods, extra
capabilities, images from registries outside the allow-list, floating tags and downgrades, dangerous
`sp_configure` options without opt-in, sysadmin-owned jobs without opt-in, SQL identifiers outside
the allowed character set. The rules that guard code execution (`sp_configure` allow-list, privileged
roles, `sa` deployments) are checked again at apply time, so they hold with the webhook disabled.

## TLS

- **Webhook and view API**: served on 9443 with a certificate generated by the chart (CA valid 10
  years, leaf renewed 30 days before expiry, reloaded without restart) or by cert-manager.
- **View API callers**: the kube-aggregator authenticates with its front-proxy client certificate,
  checked against `extension-apiserver-authentication`; then a `SubjectAccessReview` applies RBAC to
  the forwarded user. A follower that asks the leader for its plans presents the serving certificate,
  and each side pins the other's.
- **Operator to SQL Server**: TDS encrypted (`Mandatory`); the server certificate is verified only when
  `sqlConnection.trustServerCertificate: false`.
- **Between replicas**: the AG endpoints authenticate with per-replica certificates and encrypt with AES.

## Network

- Operator pods: egress only to DNS, the API server, SQL Server, the other operator pods, and
  optionally HTTPS; ingress on the webhook and metrics ports.
- SQL Server pods (Cilium policy, opt-in): ingress on 1433 from the namespace, the allowed namespaces
  and the operator pods only; no egress but DNS, the other replicas and declared destinations; no
  access to the Kubernetes API.

## SQL injection

Every SQL identifier and literal built from a spec is quoted, and identifiers are also checked
against a strict character set at admission. A test fails the build when the SQL-building code
interpolates a value into an identifier or a literal without the quoting helpers.

## Supply chain

Images are built from a distroless base, signed with cosign (keyless), and carry an SBOM and a build
provenance attestation. The tags of SQL Server images are checked against a snapshot of what Microsoft
published, refreshed weekly by CI.
